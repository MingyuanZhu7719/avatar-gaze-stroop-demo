# VIVE participant recording

Run one A/B/C/D task per session: Ink colour, Word meaning or Visual search. Automatic is available in every participant build; a package explicitly built with WoZ also offers **Use a second-PC WoZ operator** for all three tasks. Give each person one study code from P001 to P999. Issue codes consecutively and use the same code for all tasks and any repeat attempt. Keep the enrollment register separately from the recording folder. Use a separate package/data folder for hardware rehearsals so that test records do not enter the participant dataset.

1. Open the outer `AvatarStroopViveEyePreview.exe` in the participant package. Enter the participant code, select the task and choose Automatic or WoZ if available. Review the assigned four conditions and stimulus lists before preparing the session. Each launch creates a fresh session identity even if the code and task are repeated. Changing control mode does not change the participant's assignment.
2. Prepare local recording and start the classroom. Have the wearer make the two on-headset recording choices. The tutorial and ten-question exam record task responses. Eye recording starts with the first formal countdown after an exam score of at least 8/10 and the formal readiness checks.
3. For Automatic, confirm the plan and begin the first block. For WoZ, use the matching Operator package and follow the [Photon room workflow](woz-easy-pairing.md): join the room, accept the participant on the operator PC, explicitly permit forwarding/storage, connect, then begin the block on the participant PC. Local recording and live participant-avatar sharing remain separate choices. Following the fourth block and its questionnaire, allow the recorder to finish closing, then open the CSV. Each run has its own session folder under `LocalParticipantData` by default. Keep interrupted attempts separate when reviewing completed sessions.
4. Load the completed CSV **or** its matching VRAW into the updated study analyzer. Use `participant_id` to link tasks, `participant_task` to identify the task, `control_mode` to distinguish Automatic from WoZ, and the session ID to distinguish attempts. Verify the assigned condition and list for each block before comparing results. Assigned Automatic recordings retain VRAW0006; assigned WoZ recordings use VRAW0007. Use the matching updated analyzer for the latter.

Participant eye tracking loss does not stop answers or the task. The recorder marks unavailable intervals and recovery; inspect `eye_availability.csv` and sample validity before using eye measures. This does not bypass controller/headset readiness, operator source validity, network freshness or file-write failures. Operator eye/source requirements remain separate. Fine eye/face accuracy is still on TODO, not accepted by this software update.

Photon may retain the last received operator pose for up to 300 ms. Display observations beyond 150 ms are recorded and reported in `woz_pose_holds.csv`; a fresh pose ends the hold. Beyond 300 ms the task stops, as it also does if the separate task lease or authority becomes invalid. This policy applies to the forward avatar shown to the participant. It does not extend manual LAN timing, extend the reverse participant-avatar display, or create participant eye samples. Both PCs need matching packages.

## Allocation

The four Williams orders are ABDC, BCAD, CDBA and DACB. Within each consecutive enrollment group (P001–P004, P005–P008, and so on), each task uses all four orders. Each condition receives each of the four stimulus lists once. Across sixteen consecutive slots starting at P001 and each subsequent group of sixteen, each order is paired with all four list rotations. B's initial gaze is also balanced. A participant's code and selected task fully determine the plan, so repeating a task reproduces its allocation. Missed sessions and withdrawals can make the observed sample uneven. The researcher selects which of the three tasks to administer first.

The raw session header and readable CSV carry the participant code, task, allocation scheme, block order, zero-based list indices and B's initial gaze target. Existing developer recordings can be analyzed alongside participant runs and have no assigned participant code. Fine eye-versus-face gaze accuracy remains on the [validation backlog](TODO.md).

## Build

Use the isolated Unity project preparation in `docs/development.md`. Run `scripts/build-vive-stroop-preview.py` with `--participant-recording`, the pinned Unity editor, the prepared project, and a new output directory. Add `--legacy-woz-recording-development --photon-config <private-json>` for the combined Automatic/WoZ participant package, and build the matching Operator from the same revision with `scripts/build-vive-woz-operator-preview.py`. Retain generated manifests. Build the matching analyzer with `scripts/build-study-analyzer.py`. These flags select capabilities; they do not start a session or consent to recording.
