# Data export and participant gaze schema

Schema version: `avatar-stroop-csv-1`; current software version: `0.3.0-dev`. The portable implementation is in `Assets/Stroop/Core/AuditExport.cs` and `ParticipantGaze.cs`. These are in-memory append-only audit containers, a CSV snapshot exporter, and descriptive gaze-duration calculations. Hardware acquisition, apparatus calibration, display-photon timing, automatic AOI classification, and validated clock synchronization are not supplied by these components.

## Export a snapshot

On the experiment owner thread, construct an `AuditLog` with the exact session ID and run kind, optionally supplying a separate `ParticipantGazeLog`. Append actual observations as they arrive. Call:

```csharp
var provenance = new ExportProvenance(
    "participant-app-exporter",
    "Unity frame acknowledgement proxy; not display-photon onset",
    "application first button-down edge",
    buildSourceDigest); // null becomes explicit "unavailable"
ExportResult result = AuditExporter.Export(experiment, audit, exportParent, provenance);
```

The example timestamp semantics describe a software adapter; replace them with the precise semantics of the caller. `stimulus_onset_recorded=true` means the core received `MarkPresented`, and does not by itself establish physical display onset. Build/source identity must be supplied from actual build evidence; an unknown digest is never replaced with an invented Git revision. Protocol and software versions come from `SessionConfiguration`. `build_source_digest` is explicitly `unavailable` when the caller supplies no evidence. The current Unity development export uses that default. The independent-process integration script computes `sha256:` plus a digest over the ordered Core/Runtime source paths and bytes and `Apps/SimulatorHost.cs`, then passes it through `STROOP_BUILD_SOURCE_DIGEST`; this is a source-input digest, not a binary hash or Git commit.

Audit records accumulate in process memory and are persisted only when an export is requested. This is not a continuous on-disk journal or a crash-safe streaming recorder: a process failure before export can lose its accumulated audit. Export reads the current records into strings before file IO. Callers must serialize mutation/export on the owner thread; these classes are not concurrent collections. Partial sessions can be exported without ending them. No future trial, response, questionnaire answer, completion event, or sample is synthesized. Pending/interrupted trials retain their actual outcome; correctness and RT are blank unless a response was accepted. `allocations.csv` includes all four **assigned** block lists even when unattempted; it does not assert those blocks were run.

Each export creates a new timestamp/GUID directory under the explicitly supplied parent. The session ID is data and is never interpolated into a filesystem path. Files are created with `CreateNew` as `.partial`, flushed, closed, and renamed without overwrite. `manifest.csv` is written last with each data file's SHA-256 and row count. A complete final manifest means `complete_bundle=true`: all the snapshot files were finalized. An incomplete study can therefore have a complete, hash-valid snapshot bundle. A bundle interrupted during writing, without a finalized valid manifest, is a partial file bundle regardless of the session phase. This is independent of `session_completed`, which is true only for the core's actual `EndReason.Completed`. Withdrawal, technical termination, and an in-progress session remain false.

Check `ExportResult.Success` before reporting success. An IO/permission/path failure returns `Success=false`, `Error`, and the current `FailedFile` and retained `DirectoryPath` when available. Partial artifacts are preserved for diagnosis; no final manifest is generated after an earlier failure. Retry creates a fresh directory. Consumers must require a finalized manifest and verify hashes before treating a bundle as complete. SHA-256 detects accidental modification; it is not an authenticity signature. An OS crash, directory-entry persistence, or power loss after return is outside this implementation's durability guarantee. No storage/access/retention/withdrawal policy is selected here.

## Common encoding and provenance

All CSVs, including the manifest, have these columns:

`schema_version, protocol_version, software_version, session_id, run_kind, data_label, block_index, segment, trial_id, source`

- UTF-8 without BOM, comma-delimited, CRLF record endings; commas, quotes, CR and LF inside cells are quoted and embedded quotes doubled.
- Doubles use invariant culture and round-trip formatting; booleans are `true`/`false`. Blank nullable fields mean unknown/not recorded/not applicable according to their column, not zero. Invalid raw directions/rotations are preserved, including nonfinite values, with validity flags; derived intervals cannot treat them as valid gaze.
- Block, segment and planned trial indices are zero-based. Practice block is `-1`. Session-level fields are blank when no block/segment applies. Trial IDs are preserved verbatim.
- `data_label=SIMULATION` on every row of a simulation session, even when automatic control generates its avatar. Source remains independently recorded (`Automatic`, `LiveOperator`, `Simulator`, `RealDevice`, or an explicitly named non-sample origin such as `session_engine`). A simulation run with a real measurement still remains a simulation run.
- Empty tables retain their headers. Their manifest rows retain session/version/run-kind provenance and zero row counts.
- Raw source times are local monotonic readings in their named clocks. A similar numeric timestamp on another clock does not establish alignment. `session.csv.task_clock_id` identifies the engine clock for trial/rating timestamps.

## Files

| File | Record and interpretation |
|---|---|
| `session.csv` | Current phase and end reason; exact completion status; seed, allocation, condition order, B initial target, list indices, practice attempt count, explicit countdown/language; exporter/build identity, stimulus/response timestamp semantics, current record counts and engine clock. One snapshot row. |
| `allocations.csv` | Assigned condition, list index and full deterministic list ID for each block; seed; the selected control when the block was actually locked, otherwise blank. Assignment does not imply observation. |
| `events.csv` | One engine journal event: original event sequence, timestamp, clock and kind. |
| `event_fields.csv` | Original key/value payloads linked by event sequence, including preparation evidence, owner/source locks, state changes, pauses, rest, faults and reasons. Multiline values are preserved. |
| `trials.csv` | Attempted/current planned trials only: practice/attempt, condition, actual list ID/seed/index, word/ink/congruency, outcome, onset-recorded flag, onset/response timestamps, first response, nullable correctness/RT, technical flag, selected control and timestamp semantics. |
| `ratings.csv` | Individual item ID, value, timestamp, language and wording version; block, segment and condition. No summed score is manufactured. |
| `operator_samples.csv` | Raw operator-control samples appended to this audit: stream/device/clock and contextual sample identity, capture/send timestamps, raw head quaternion and eye direction, separately reported and derived head/eye validity. In `ParticipantSimulationApplication`, this contains receiver-accepted samples only; it is not a complete source-acquisition record. |
| `participant_samples.csv` | Independent participant measurement stream/device/clock/sample identity and capture time; raw eye direction and separately reported/derived eye validity. No operator sample conversion exists. The current simulation applications attach no participant measurement stream, so this table and all three gaze tables are header-only. |
| `gaze_windows.csv` | Caller-observed phase windows in one named reference clock, block/segment/condition and explicit active-task flag. Windows describe the supplied observation period, including a partial run if exported mid-task. |
| `gaze_intervals.csv` | Caller-classified exclusive interval, sample and trial linkage, phase/condition, reference clock, start/end, AOI, validity and mapping/calibration versions. Explicitly labelled `caller_classified_no_geometry_validation_claim`. |
| `gaze_summary.csv` | Per block/segment descriptive duration and denominators for the configured participant stream. Details below. |
| `avatar_presentations.csv` | Evaluation or render-observation time/clock/semantics, phase, protocol visibility, selected/actual source, input status/validity, mapping/geometry versions and raw input linkage. Distinct `reference_*`, `mapped_*`, and `applied_*` poses, plus nullable renderer observation/held/visibility flags. See the field meanings below; this filename alone does not establish that a frame was rendered. |
| `clock_audit.csv` | Caller observations with source/reference clock and mapping version. Offset is **source minus reference** at `observed_reference_seconds`; drift is source relative to reference in ppm. Uncertainty and estimates are nullable; evidence describes estimator and limitations. No automatic claim of synchronization. |
| `transport_audit.csv` | Transport event kind, receive clock/time, stream, **packet sequence and source sample sequence separately**, nullable missing-sample/latency/jitter observations, clock-mapping version and detail. A sequence gap is an arrival-time inference, not proof of permanent loss; encode that in kind/detail. Latency/jitter require clock-mapping provenance; their endpoints and estimator must be stated in kind/detail. |
| `manifest.csv` | A row for every data file, SHA-256, row count, finalized-bundle and actual session-completion flags, exporter ID and common provenance. The manifest does not hash itself. |

`AuditLog` provides `RecordOperatorSample`, `RecordPresentation`, `RecordClock` and `RecordTransport`; its lists expose read-only views. `AvatarPresentationRecord` snapshots the output values at construction instead of retaining mutable reference state. Repeated presentations of one acquired sample are permitted and retain its sample link. Within the session, raw operator duplicate `(stream_id, block_index, segment, sample_sequence)` observations are rejected; sequence numbering may restart after a block/segment change. Presentation input linkage uses the same block/segment context plus `input_stream_id` and `input_sequence`. Participant sample sequences remain unique across their entire configured participant stream. Duplicate transport packets belong in the transport event table. A stream cannot silently change device, clock or source identity. Simulator sample/presentation/transport data is rejected by an apparatus audit log. Current `Experiment` also blocks apparatus sessions pending the apparatus prerequisites.

## Avatar evaluation and renderer observations

`AvatarPresentationRecord.ActualPose` is the controller's mapped output. Its CSV names are deliberately `mapped_head_x/y/z/w` and `mapped_eye_x/y/z`; there are no `actual_head_*` or `actual_eye_*` CSV columns. The renderer may retain a previous valid component when current input is unusable, so the mapped pose and the applied pose can differ.

| Column group | Meaning |
|---|---|
| `reference_head_*`, `reference_eye_*`, `reference_phase`, `reference_from/to`, `reference_active_seconds`, `reference_cycle_seconds`, `transition_fraction` | Prescribed reference pose and schedule evaluated at the active clock; these do not measure realized human dwell/turn timing. |
| `mapped_head_*`, `mapped_eye_*` | Controller mapping result from the selected source, nullable when unavailable. `head_valid` and `eye_valid` refer to usable controller input, independently for each component. Retained mapped values can be invalid. |
| `applied_head_*`, `applied_eye_*` | Renderer-state pose captured for the camera observation. Blank when no renderer-state observation was supplied; a valid-looking applied pose does not repair invalid input. |
| `renderer_head_held`, `renderer_eyes_held` | Whether each renderer component was retained instead of newly applied from current valid input. These flags are independent, and do not constitute an approved apparatus fault policy. |
| `avatar_visible` | Controller's protocol visibility request. It does not prove the avatar was included in a rendered frame. |
| `renderer_visibility_requested` | Captured renderer hierarchy's active visibility request. It can be false for a hidden avatar; it is distinct from a renderer witness and physical visibility. |
| `renderer_observed` | Whether any avatar renderer was witnessed by the selected camera during the completed observation. `true` is a software camera-render witness, `false` is an observation without such a witness, and blank means no renderer observation was supplied. None establishes display-photon timing or participant perception. |
| `timestamp_semantics`, `presentation_clock_id`, `presentation_local_seconds` | The caller's exact observation endpoint and clock. Interpret these before treating a row as presentation evidence. |

A renderer record supplies the applied pose, observed flag and both held flags together. The current Unity adapter also supplies renderer visibility and captures the input output/context before camera rendering, emitting only if the captured state remains unchanged through camera completion. `actual_source` identifies the controller input source; when a component is held, that field alone does not identify the older sample that originally produced the retained component. The frame history and held flags must be considered together.

The headless process calls `RecordControllerEvaluation`, which writes `timestamp_semantics=headless_controller_evaluation_not_rendered`. Its `renderer_observed`, both held flags, `renderer_visibility_requested`, and all `applied_*` columns are blank. `mapped_*` or `avatar_visible=true` in those rows must not be counted as verified rendered exposure. The current saved integration bundles contain only this headless form. The Unity code can emit camera-proxy observations, but no Unity-rendered records have been verified in this environment.

## Source acquisition and receiver evidence

The operator simulation process retains `AcquiredSamples` before transmission. At normal process completion, `Apps/SimulatorHost.cs` writes a separate `operator-acquisition.tsv` alongside `operator-report.tsv`, outside the participant CSV bundle. The TSV contains `data_label`, session/stream/device/clock, block/segment/sample sequence, capture/send time, raw head quaternion and eye direction, and reported head/eye validity. Values are synthetic and labelled `SIMULATION`. Its row count equals the report's `samples_sent + samples_send_failed + samples_suppressed`: successful socket acceptance, a terminal reset during a sample send, or deliberate simulation-script suppression after acquisition. A failed sample is retained and counted once; later ticks cannot acquire/send again in the closed epoch. `samples_sent` is not a delivery acknowledgment, and the sample's `send_seconds` is the attempted-send timestamp even if the send fails or is suppressed. The report includes the explicit `connection_fault` operation when a reset occurs. The TSV has its own fixed schema, is not covered by the participant bundle manifest, and is also written from memory at shutdown rather than streamed durably.

On the receiving process, `operator_samples.csv` contains only accepted head/eye packets. Rejected/undecodable packet observations and monitor faults are recorded in `transport_audit.csv`; their detail distinguishes decode failure, packet kind, rejection reason or fault. Packet ordering uses `packet_sequence`; a head/eye payload separately retains `source_sample_sequence`, with the sample's block/segment in the common columns. Context for a decoded sample comes from that payload, whereas a non-sample event uses the application's current context. A received sample's linked `trial_id`, when available, is the current receiving task and is not proof of which trial was active at remote capture time.

Compare source and receiver records using session, stream, block, segment and sample sequence. Receiver rejection does not erase source acquisition. Arrival gaps do not prove permanent loss, and the final source/receiver observation periods can differ. The current runtime records `missing_samples` from inferred packet-sequence gaps; that legacy CSV column counts missing sequence positions across packet kinds, not necessarily missing head/eye samples. Latency and jitter remain blank in this runtime's transport records. Clock estimates are separately logged as version 2 development affine observations with explicit uncertainty/evidence, point-estimate method and unavailable reason; timestamps and estimates do not establish validated end-to-end display latency.

Both headless roles additionally write a bounded diagnostic TSV (`participant-clock-exchanges.tsv` and `operator-clock-exchanges.tsv`), retaining the last 256 correlated replies. It records exchange ID, named local/remote clocks, all four timestamps serialized for exact double round-trip, reply acceptance/rejection, map availability/reason/revision, retained sample count, feasible rate bounds and point-estimate method. These diagnostic TSVs are outside the participant manifest and do not claim clock accuracy. They make timing failures inspectable; on verification failure the script also writes this bounded evidence to CI logs. The final integration report retains its availability assertion.

The current simulation application constructs `AuditLog` without a `ParticipantGazeLog`. Consequently, `participant_samples.csv`, `gaze_windows.csv`, `gaze_intervals.csv` and `gaze_summary.csv` are empty apart from headers and have zero manifest row counts. This is missing independent participant measurement, not zero participant gaze, zero task attention, or a measured tracking-loss rate. Empty tables alone do not encode a missingness reason; the runtime configuration and this documented limitation supply that context. Operator control samples never fill those tables.

## Independent participant measurements and AOIs

`ParticipantEyeSample` uses `ParticipantEyeSource.RealDevice` or `.Simulator`, and explicitly requires `StreamRole.ParticipantMeasurement`. It cannot be constructed with the operator role or a `LiveOperator` source. `ParticipantGazeLog` fixes its session, run kind, independent stream/device, source and reference clock. The first sample fixes its capture-clock identity. Simulator streams require the `simulator/` prefix. Wrong-session/source/stream/device, duplicate sample sequences anywhere in that configured participant stream, and capture-clock changes are rejected. The participant log does not currently support a sequence restart on a block/segment change. When attached to an `AuditLog`, operator samples cannot reuse the participant stream or device identity.

Caller responsibilities remain substantive: obtain independent participant acquisition; validate calibration and AOI geometry; establish the source-to-reference time mapping; classify eye samples; and supply the actual duration each classification represents. `mapping_version` must identify the classification/time-mapping procedure, and `calibration_version` its calibration record or explicit unvalidated simulation fixture. Merely supplying labels does not validate them. No acquisition interval is inferred from neighboring samples, and no last sample is extended through a dropout. Sample count alone is not dwell time.

`GazeObservationWindow` and `ParticipantGazeInterval` are immutable half-open intervals `[start,end)` with positive finite duration. Windows cannot overlap and a block cannot change condition. Intervals must fit in their registered window and match the registered participant sample's block/segment. Exclusive AOI intervals cannot overlap; adjacent intervals may share a boundary. Only `Phase.MainTask` windows contribute to summaries. Practice, preparation, countdown, pause, questionnaires and rest are excluded. The caller must close/reopen windows at actual active-clock boundaries, including interrupted and resumed segments; a partial export includes only windows whose actual endpoint has been observed.

AOIs are `Task`, `Eyes`, `RemainingFace`, `Other`, `Invalid`, and structural `NotApplicable`. `EyeValid` requires the device-reported eye-valid flag and a finite unit direction; head validity is irrelevant. Unit tolerance is a numeric representation check, not a tracking-quality or calibration threshold. Invalid samples must classify as `Invalid` and cannot become `Other`. Valid samples cannot classify as `Invalid`. `NotApplicable` is reserved for structural outcomes and is not a catch-all interval classification.

| Quantity | Definition |
|---|---|
| `active_seconds` | Sum of supplied, nonoverlapping MainTask windows for this block/segment. |
| `valid_seconds` | Sum of valid classified active intervals: Task + Eyes + RemainingFace + Other. |
| `invalid_seconds` | Sum of active intervals explicitly classified Invalid. |
| `unobserved_seconds` | Active duration without any classified valid or invalid interval; no gap filling. |
| `valid_coverage` | Valid seconds / total active-task seconds. |
| AOI proportion | That AOI's seconds / valid active-task seconds; null if there is no valid denominator. |
| `combined_face_seconds` / proportion | Explicit Eyes + RemainingFace combination; never counted as an additional exclusive category. |

In D, eyes/remaining-face intervals are rejected because the avatar is absent. `avatar_aoi_applicability=NotApplicable`; eyes, remaining-face and combined-face durations and proportions are blank, not zero. Task remains applicable and uses the same valid active-task denominator. An active window with no measurements has zero coverage and null proportions; its full duration is unobserved. No summary row is created when no MainTask window was supplied. Exported intervals retain mapping/calibration versions so analysts can inspect revisions rather than assuming calibration quality is uniform.

## Verification scope

`Tests/DataTests.cs` registers fourteen portable regression cases covering CSV escaping/invariant culture, partial/pending/interrupted records, full and withdrawn completion, unique no-overwrite exports, file hashes/row counts, explicit filesystem failure, source/role/device/session partition, active-time AOI denominators, D structural N/A, invalid-versus-Other separation and overlap/context rejection. The clock audit regression exports 80 mapping updates beyond the 64-observation retained window, then exports same-count invalidation; monotonic mapping revisions prevent later estimates from disappearing. Offsets retain their actual mapping reference time. Additional checks preserve per-context operator sample identity and distinguish mapped input from an applied held renderer pose. Those renderer records are test fixtures, not observations from a running Unity scene.

The current independent-process integration scenarios have produced and validated real filesystem exports. `scripts/integration.py` runs separate local operator and participant processes over loopback UDP, verifies matching task snapshots, clock/source provenance, faults or acknowledged safety stop, every participant-bundle file hash and row count, source-acquisition row counts, explicit absence of participant eye samples, and absence of headless renderer claims. The fault scenario ends in `Rest` after one block and ratings; the safety-stop scenario ends `Paused` with an interrupted trial. Both correctly export `complete_bundle=true` and `session_completed=false`. This verifies software processes and snapshot data on one host, not two physical computers, headsets or measured rendered exposure.

The portable C# 7.3 code and Unity adapter code have passed managed compilation using the locally installed Unity compiler/runtime and assemblies. The attempted Unity Editor check could not run because no valid Editor license was available; the log reports `No valid Unity Editor license found`. Therefore Editor execution, a rendered scene, camera-observed export records, VR input, and hardware display timing remain unverified. Disk-full behavior, abrupt power loss, crash-safe continuous recording, real participant acquisition and apparatus calibration are also not claimed as validated. See `docs/development.md` for the build/integration commands and current evidence boundaries.
