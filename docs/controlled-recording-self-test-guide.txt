SOURCE DISTRIBUTION NOTE: This guide applies only to a separately built and reviewed package with the stated recording scope. This public source export includes no player and has not been tested in a headset. It requests only the short explicitly chosen self-test below, not a completed study or automatic capture.

CONTROLLED LOCAL RECORDING: SHORT SELF-TEST FIRST

Not a validated study. Use only for your own development test, not study participants. Building or opening this package starts no recording. The app does not upload files; no data upload is needed for this check. Eye/head data can be identifying. Keep files private. The installed HTC runtime may keep its own diagnostics.

CHECK THE PACKAGE SCOPE IN START-HERE / vive-classroom-build.json
- Ordinary preview: task records are in memory only until close; no eye or task files.
- Controlled named package: recording is optional only for Named explicit multi-block simulation. Legacy remains memory-only.
- Controlled legacy + named package: adds optional Legacy A/B/C/D recording. It preserves BCAD, lists 0/1/2/3, B initially facing the participant, and the original timing. It does not record automatically.
- In every package, Confirm configuration for development preview is NON-RECORDING. An on-screen memory table, questionnaire completion, eye-preview dot or file path alone is not proof of a saved recording.

FIRST CHECK: ONLY 1-2 PRACTICE TRIALS, THEN WITHDRAW
1. Keep the currently open preview until you have finished inspecting its in-memory results. When ready for this separate test, close it normally and open the OUTER AvatarStroopViveEyePreview.exe, not UnityPlayer/AvatarStroopViveEyePlayer.exe. Do not run two previews together. Finish any needed calibration in the existing installed HTC runtime first; valid calibration/runtime readiness is required, not bypassed by this build.
2. Before Start classroom view, select Legacy A/B/C/D for a legacy-enabled package, or Named explicit multi-block simulation for a named test. Select your wand. Leave bounded in-memory development observation off. Read and acknowledge the local self-test notice. If the selected design says NO RECORDING / EXPORT, memory only, or recording unavailable, stop: that is not a recording test.
3. Explicitly enter an existing private LOCAL directory, for example the empty LocalSelfTestData folder beside the outer launcher. No folder is preselected in the app. Enter 32 MiB for the recording limit, then Prepare participant recording choices. Do NOT use Confirm configuration for development preview for this flow. The limit bounds the source file, not total disk use or reserved space; source plus same-limit raw stage plus 64 MiB CSV can total roughly 128 MiB.
4. Start classroom view and follow the headset placement prompt. Keep the headset worn, tracking stable, the chosen wand connected and the app focused. Release all controls between prompts. Trigger agrees separately to task/questionnaire storage and eye/head storage; Menu declines. Both choices must be current. Changing design, losing tracking/focus, removing the headset or disconnecting a device invalidates choices. Do not try to bypass a cancellation; close normally and start a fresh test after fixing readiness.
5. After both choices, explicitly click Enable eye preview. This starts SDK sampling for diagnostics, not file recording. If calibration, tracking, input or SDK readiness is invalid, stop and report the displayed status. Calibration changes or focus loss may require a fresh test and new choices.
6. Enter 64 MiB for the separate CSV limit and 60 seconds for its cleanup timeout. With controls released and the current choices/source ready, click Start recording and request raw + analysis CSV. This separate action is required. If it is unavailable or says no recording was started, do not begin a memory-only trial and treat it as recorded.
7. Click Owner: begin practice. Answer only 1-2 trials, then use the desktop Withdraw task button. You do not need to finish practice or repeat four blocks. Trackpad colours: up red, right green, down blue, left yellow. Trigger confirms/continues; it does not manually pause a task.
8. Wait for the withdrawal/cleanup status before closing normally. A started recording may retain an incomplete raw prefix and earlier bytes. Withdrawal must leave output incomplete/UNKNOWN, with NO completed CSV receipt. It does not erase earlier data. Note the displayed status and whether local files exist; do not upload them or rename a partial file to imply success. No file means this attempt did not establish file capture.

For desktop Enable eye preview / Start recording / Begin practice, keep the HMD worn, controller tracked and app focused. If you cannot click while preserving those conditions, have a second person operate the desktop or stop. Do not remove the HMD, alt-tab or use a VR desktop overlay to reach these controls; focus/tracking loss cancels the choices or attempt.

WHAT THIS SHORT TEST PROVES
It can check explicit start, a small local recording prefix and withdrawal behavior. It does NOT prove a completed recording, valid gaze accuracy, full sample coverage, physical timing alignment, power-loss durability or four-block completion. A completed raw/CSV result needs a separately reviewed completion test and independent integrity checks; this guide does not request a long rerun.

STOPPING / FAILURES
- Desktop Withdraw task is the reliable withdrawal control, including faults. Escape works during normal/completion polling but is not handled in every failed state.
- Owner pause, focus/tracking loss or another safety interruption permanently ends that recording attempt. It is not a resumable recording pause. A late/failed operation stays UNKNOWN; do not expect a successful output receipt.
- Do not unplug hardware to force this test. Do not change permissions, run as administrator or disable safety settings. Report the status instead.
- The existing 64-bit Windows HTC SRanipal.dll 1.3.5.1 must already be installed at its calibration-dashboard location. It is not bundled, downloaded or initialized by building the package. SteamVR is selected for the launched child process only; system/Quest settings are unchanged.
