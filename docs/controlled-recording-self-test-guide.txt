PACKAGE SCOPE: This guide applies to a separately built package with the stated recording capabilities. The repository distributes source, not players or private validation records. Check the exact package manifest and its validation notes; software checks and a local headset rehearsal do not establish study acceptance. This guide requests only the short explicitly chosen self-test below.

CONTROLLED LOCAL RECORDING: SHORT SELF-TEST FIRST

Not a validated study. Use only for your own development test, not study participants. Building or opening this package starts no recording. The app does not upload files; no data upload is needed for this check. Eye/head data can be identifying. Keep files private. The installed HTC runtime may keep its own diagnostics.

CHECK THE PACKAGE SCOPE IN START-HERE / vive-classroom-build.json
- Ordinary preview: task records are in memory only until close; no eye or task files.
- Controlled named package: recording is optional only for Named multi-block. Legacy remains memory-only.
- Controlled legacy + named package: adds optional Legacy A/B/C/D recording. It preserves BCAD, lists 0/1/2/3, B initially facing the participant, and the original timing. It does not record automatically.
- In every package, Preview (no files) followed by Configure preview (no recording) is NON-RECORDING. Record locally is a separate path that still requires current headset choices and an explicit start. An on-screen memory table, questionnaire completion, eye-preview dot or file path alone is not proof of a saved recording.

FIRST CHECK: ONLY 1-2 PRACTICE TRIALS, THEN WITHDRAW
1. Keep the currently open preview until you have finished inspecting its in-memory results. When ready for this separate test, close it normally and open the OUTER AvatarStroopViveEyePreview.exe, not UnityPlayer/AvatarStroopViveEyePlayer.exe. Do not run two previews together. Finish any needed calibration in the existing installed HTC runtime first; valid calibration/runtime readiness is required, not bypassed by this build.
2. Choose Record locally, then Legacy A/B/C/D (if available) or Named multi-block. For Named, select the intended option AND stimulus list for every block. Scroll through the rows and correct any block listed as incomplete; the app does not select experimental conditions for you. Keep exactly one VIVE wand connected and acknowledge the local self-test notice.
3. Review the suggested new session folder under LocalSelfTestData. Choose a new session folder if you want a fresh proposal; it creates nothing by itself. You can instead enter your own existing private local directory. Advanced storage limits defaults are 256 MiB raw, 256 MiB CSV and 300 seconds for CSV cleanup. The limit bounds the source file, not total disk use or reserved space; source plus same-limit raw stage plus CSV can total about 768 MiB at defaults.
4. Click Prepare raw + CSV and arm recording + Practice. This may create the proposed empty session folder but saves no task or gaze data. An incomplete block plan is a setup issue, not a folder I/O error. Wait for preparation to finish and then click Start classroom view. Eye diagnostics start automatically when the view is ready; they do not save data.
5. Follow headset placement and recording-choice prompts. Trigger agrees separately to task/questionnaire storage and eye/head storage; Menu declines. Release controls between prompts. After both choices, the app waits for current tracking and neutral controls, then starts recording and Practice automatically. No extra desktop Start or Practice click, or headset removal, is required. The setup arm expires after 15 minutes; after both choices the automatic start request expires after 3 minutes. An expired or canceled request does not restart on its own.
6. When Practice appears, answer only one or two practice trials, then use desktop Withdraw task. Trackpad: up red, right green, down blue, left yellow; threshold 0.5. A normal run still requires the operator to confirm the formal plan and then separately choose Begin first block. This short check does not reach those actions.
7. Wait for withdrawal and cleanup before closing. A started recording may retain an incomplete raw prefix; withdrawal does not erase earlier bytes or produce a normal completed-session CSV receipt. No file means this attempt did not establish file capture.

Desktop focus changes alone do not stop recording. XR focus loss holds task input/presentation; healthy raw capture can continue. After XR focus returns, Automatic/NoAvatar require released controls and an explicit Trigger to resume. Recognized same-reference headset pose loss or same-device controller pose loss can hold the current session and record a gap, without inventing missing samples. After stable valid input, an affected trial can retry with a new presentation and reaction time; earlier completed responses are retained. LiveWoZ does not restart its old source. After explicit recording start, repeated, frozen, invalid or absent eye data does not pause, retry or stop the task. The Excel-readable CSV marks NO_NEW_SAMPLE or MISSING at software-observed times, with reason and task cursor; gaze fields on these metadata rows are empty. These are measured software observations, not invented hardware dropped-frame counts. Unrecognized actual tracking loss of the head/controller, device/reference/shared-clock changes, or storage faults remain separate safety boundaries. The app does not switch controller identity mid-session.

RECORDING READINESS AND PRESENTATION
Initial recording readiness uses bounded, verified eye history from the same live worker together with current head/controller/neutral evidence. A new eye frame need not coincide with the exact Unity update that processes Start. Pending Start reports the specific missing input or claim; removing the headset is not a required start step.
After Start, contention while reading the eye snapshot is a measurement-only MISSING/SNAPSHOT_BUSY observation, not a task pause or automatic retry. Its metadata distinguishes software snapshot contention/coherence change from physical sensor loss. Actual task/head authority, writer failure, explicit withdrawal and genuine tracking/focus holds remain separate.
The recorded automatic Legacy presentation applies the current avatar output before reveal: B/C/A show their respective automatic behavior during Main, D intentionally hides it, and Practice has no avatar. Software renderer witnesses do not establish physical headset visibility. Preserve original records when reviewing a failed or incomplete test.
WHAT THIS SHORT TEST PROVES
Package-specific validation is recorded with the build deliverables. A synthetic harness can exercise the local writer, plan receipts, render callbacks, responses, normal completion and CSV readback; those checks do not prove physical visibility or gaze accuracy. Any wearer rehearsal also needs its stated scope and results. If you choose this short self-test, it can check explicit start, a small local recording prefix and withdrawal behavior. It does NOT prove completed recording, gaze accuracy, full coverage, physical timing alignment, power-loss durability or four-block completion. A completed raw/CSV result needs separate review; this guide does not request a long rerun.

STOPPING / FAILURES
- Desktop Withdraw task is the reliable withdrawal control, including faults. Escape works during normal/completion polling but is not handled in every failed state.
- Owner stop/pause, withdrawal, unrecoverable head/controller/recording-authority errors or storage failures can end recording. Focus loss alone does not end it. A recoverable pose hold is distinct from a stopped writer; a late/failed operation stays UNKNOWN. Do not expect a completed output receipt.
- Do not unplug hardware to force this test. Do not change permissions, run as administrator or disable safety settings. Report the status instead.
- The existing 64-bit Windows HTC SRanipal.dll 1.3.5.1 must already be installed at its calibration-dashboard location. It is not bundled, downloaded or initialized by building the package. SteamVR is selected for the launched child process only; system/Quest settings are unchanged.
