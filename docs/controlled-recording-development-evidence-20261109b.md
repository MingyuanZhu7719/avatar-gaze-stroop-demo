# Controlled local recording Development source

Date: 2026-11-09. This is a separate opt-in Windows XR development self-test version, not a validated study release. No study participant use is authorized by this source. The application does not upload local recording files; the installed vendor runtime may maintain its own device diagnostics.

## Build availability and explicit choices

The six recording/export availability gates forward to the unchanged immutable ViveControlledRecordingBuildPolicy. It permits exactly one of 1,024 combinations: the explicit controlled-recording define, Windows Unity XR player symbols and DEVELOPMENT_BUILD must all be present; Editor, Unity tests, regression tests and synthetic fixture symbols must all be absent. Ordinary and Editor builds remain unavailable. No runtime switch, persistent preference or mutable policy override is added.

Availability is not permission to capture. The owner notice defaults to unaccepted and is checked at preparation, start eligibility and installed creation. The two separate headset storage choices, explicit eye-preview start and explicit recording/output start remain required. Existing source binding, readiness, bounded capacity, per-operation authority, withdrawal and file identity checks remain in place. Recording defaults to off.

The public source preserves the strict build policy. It disables both legacy native fixture allowlists and the integration fixture root before filesystem work, removes machine-specific paths, and keeps native fixtures, raw logs, private packaging helpers and binaries out of the export. ## Acceptance still required

Do not treat this source as hardware-tested. Real SDK delivery, gaze accuracy, physical timing alignment, complete sample coverage, informed study consent and power-loss durability remain unvalidated. A separately reviewed controlled package and explicit local self-test must be followed by independent raw/CSV reconciliation. With the specified two-block plan, no practice retry and no interruption, expected counts are 56 trials and 10 ratings; otherwise reconcile actual events.

Owner pause, focus loss and safety interruptions end the current recording attempt rather than create a resumable pause. Desktop Withdraw task is the reliable control after a fault; Escape is not handled in every failed state. Withdrawal does not erase retained bytes. Keep UNKNOWN outputs unknown and do not rename partial files as a completed study. A 32 MiB source plus same-limit raw stage and 64 MiB CSV may retain about 128 MiB.

The self-test guide is intended only for a separately built and reviewed controlled package. Building or publishing this source does not collect data, authorize a real session, or satisfy hardware acceptance.
